## The bug

On the live Camps page, the Team & town camps code card shows at the top
under "All programs". Root cause (checked by Claude in chat): the built
HTML and current `site.js` are correct (fresh headless browser hides it),
but `assets/js/site.js` is served WITHOUT a version query and with
`cache-control: public, max-age=604800`. Returning visitors run the
pre-round-31 `site.js`, which knows nothing about `data-filter-only`, so
"All" un-hides every card that has `data-tags`, including this one.
`site.min.css` already has `?v=<hash>`; the JS does not.

## The changes

1. Cache-bust every script the site loads (`site.js`, `register.js` and
   any other local JS) with the same `?v=<content hash>` pattern the CSS
   already uses, generated by `build.mjs` so it changes whenever the file
   changes. Apply on every page.
2. Make the card immune to stale JS: the team code card must not be
   something an old `site.js` can un-hide. Take it out of the filtered card
   set (no `data-tags` on it, so old filter code ignores it). New `site.js`
   shows it only when the active filter is `team-town` and hides it for
   every other filter, including All. It stays `hidden` in the HTML, so
   without JS it never shows.
3. Move the card to the bottom of the programs section, after the
   program grid (and after the empty-state message). Under Team/Town it
   is then the only thing showing; under every other filter it is not
   rendered at all.
4. Keep everything else about the card exactly as round 31 built it.
